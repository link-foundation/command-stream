Fixes #209.

Pages was disabled, so deployment and the advertised documentation link returned 404. npm verification failed before a successfully published version became visible. Passing CI also concealed release-guard bypasses, skipped dependency review, audit transport failures and five Rust size warnings. Final review reproduced unrelated staged files, repeated deleted-fragment staging failures and a stale release tag after a Git push race.

This PR repairs Pages/dependency-graph settings, hardens both languages' release/version/changelog checks, authenticates publishing access before package checks, checks every release mutation, and uses allowlisted native Git staging with bounded lost-race retries. Exact-version registry polling has a finite visibility budget. Manual releases require successful checks on main; parity exemptions preserve executable checks; source changes trigger benchmarks; runners and script tooling are pinned. Rust modules are split while preserving public exports. Both patch-release fragments prepare automatic versioning.

Bun console/JUnit artifacts and existing tracing preserve failure evidence with diagnostics off by default. A reproduced Bun upstream reference failure retains every assertion and uses the existing bounded reference-only retry policy for one case; command-stream implementations remain strict. Four deterministic policy tests cover recovery, persistent failure, implementation failure and unmarked cases.
